# Reusable Workflows

Reusable Workflows is the shared automation repository for Node.js projects, npm packages, VS Code extensions, documentation sites, and other Moya repositories.

## Public automation surface

| Type                 | Location                                                 | Contract                    |
| -------------------- | -------------------------------------------------------- | --------------------------- |
| Reusable workflows   | `.github/workflows/reusable_*.yml`                       | Public                      |
| Reusable actions     | `actions/*/action.yml`                                   | Public                      |
| Scripts and tooling  | `scripts/*`                                              | Documented reusable tooling |
| Repository workflows | `.github/workflows/*.yml` without the `reusable_` prefix | Internal                    |

Start with [Getting started](./01-getting-started/page.mdx), browse the [workflow catalog](./02-workflows/page.mdx), or see [Development](./04-development/page.mdx) for repository structure and maintainer guidance.

## Independent release lines

Reusable Workflows has two public version lines:

| Surface                        | Version source          | Release tag                           | Changelog                |
| ------------------------------ | ----------------------- | ------------------------------------- | ------------------------ |
| npm package                    | `package.json`          | `@moyarich/workspace-tools@<version>` | `CHANGELOG.md`           |
| Reusable workflows and actions | `release version` | `workflows-v<version>`                | `CHANGELOG.md` |

Reusable workflow consumers should pin `workflows-v<version>` or the compatible moving major alias `workflows-v<major>`.

Both release paths use the generic `reusable_release.yml` GitHub Release layer. Release preparation leaves the matching GitHub Release as a draft until the corresponding publish/finalization step completes.

## Copyable examples

Consumer-ready workflow callers live under `examples/`. Each example is a first-class repository example, such as:

```text
examples/
├── github-pages/
│   └── workflow.yml
├── node-ci/
│   └── workflow.yml
└── ...
```
