# Release Drafter workflow

Use `reusable_release-drafter.yml` to prepare release notes without creating a Git tag or publishing a GitHub Release. This is a **draft-only** workflow, not the repository release or npm publishing workflow.

For this repository, manually run `.github/workflows/release.yml` to publish the GitHub Actions release and update version tags. For npm package consumers, use `reusable_npm-release.yml` for package release preparation and `reusable_npm-publish.yml` for registry publication; publishing does not create the package release.

## Copy and paste

```yaml
jobs:
  release:
    uses: moyarich/reusable-workflows/.github/workflows/reusable_release-drafter.yml@main
    permissions:
      contents: write
    with:
      target-branch: main
      version: 0.2.0
      release-name: My Project v0.2.0
      changelog-path: CHANGELOG.md
      dry-run: true
      workspace-tools-source: registry:npm:0.2.0
```

## Draft behavior

When no matching draft exists, the workflow creates one and seeds its body from the matching `CHANGELOG.md` entry.

When a matching draft already exists, the workflow reuses it and preserves its body so maintainer edits are not overwritten.

## Inputs

| Input            | Required | Default        |
| ---------------- | -------- | -------------- |
| `version`        | Yes      | —              |
| `release-name`   | Yes      | —              |
| `target-branch`  | No       | `main`         |
| `changelog-path` | No       | `CHANGELOG.md` |
| `dry-run`        | No       | `true`         |

A manual preview in this repository uses `gh workflow run reusable_release-drafter.yml --repo moyarich/reusable-workflows --ref main -f target=repository -f version-selection=auto -f dry-run=true`. Consumer repositories dispatch their own caller workflow.
