# Check dist

The `reusable_self-heal-check-dist.yml` workflow rebuilds selected npm workspace distributions using the caller repository's `.github/check-dist-config.yml`.

## Distribution modes

There are two different cases:

| Mode                          | `commitDist`      | Behavior                                                                                                                                                                                                            |
| ----------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Committed distribution**    | `true`            | Generated files (for example `dist/`, `actions/`, or extension bundles) are checked into Git. Rebuild and compare them with committed files, and optionally commit regenerated output when self-healing is enabled. |
| **CI-generated distribution** | `false` (default) | Generate output during CI, packaging, or publishing without requiring that output to be checked into Git. Build and validate the output; do not stage, compare against Git, or commit it.                           |

Only committed distributions need to match checked-in build output. For CI-generated distributions, the output directory may be absent **before** the build. It still must exist **after** the build for artifact validation.

A repository can mix both modes across different packages. Publishing an npm package does not, by itself, require committing its `dist/` directory.

## Configure the caller

Create `.github/check-dist-config.yml` in the consuming repository, or select a different file using the workflow's `config-path` input. The schema is maintained centrally in [check-dist-config.schema.json](https://github.com/moyarich/reusable-workflows/blob/main/.github/reusable-configurations/check-dist-config.schema.json).

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/moyarich/reusable-workflows/main/.github/reusable-configurations/check-dist-config.schema.json
packages:
  all:
    commitDist: false
    distPath: "{packageDir}/dist"

  "packages/actions":
    commitDist: true
    distPath: actions
    buildCommand: npm run build:actions

  "packages/cli":
    distPath: packages/cli/dist
    buildCommand: npm run build:cli
```

`packages.all` provides shared defaults. Entries keyed by package name or directory override individual fields. Distribution paths support `{packageDir}`, `{package}`, `{packageName}`, and `{workspace}` placeholders. Use `extraPackages` for build targets not returned by workspace discovery.

## Call the reusable workflow

```yaml
jobs:
  check-dist:
    uses: moyarich/reusable-workflows/.github/workflows/reusable_self-heal-check-dist.yml@main
    permissions:
      contents: write
    with:
      config-path: .github/check-dist-config.yml
      package: all
      dry-run: true
      commit: false
```

The caller workflow templates are maintained in [reusable-workflows-callers](https://github.com/moyarich/reusable-workflows-callers).

The `commit` workflow input controls whether an eligible committed distribution is pushed back to Git. `dry-run: true` prevents commits even for `commitDist: true`. Packages with `commitDist: false` are never staged or committed by this check.

## Failure behavior

- Invalid YAML or values that violate the schema: fail configuration validation.
- Selected package build fails: fail.
- Expected output directory still missing after the build: fail.
- Committed distribution differs from Git: report the difference and allow the configured self-heal behavior.
- CI-generated distribution absent before the build: not an error.


## Workflow dispatch inputs

The `actions/workflow-dispatch` action accepts `required_workflows` (one or more comma-separated workflow filenames) and optional `workflow_inputs`, a JSON object keyed by filename. Each target receives only its own `workflow_dispatch` inputs:

```yaml
- uses: ./actions/workflow-dispatch
  with:
    required_workflows: ci_check-dist.yml,_self-test_typed-input-parser.yml
    workflow_inputs: >-
      {"ci_check-dist.yml":{"package":"all","dry-run":true},
       "_self-test_typed-input-parser.yml":{}}
    branch: ${{ github.ref_name }}
    sha: ${{ github.sha }}
    token: ${{ github.token }}
    sha-input: ""
```

This action can be used inside a workflow started by either `workflow_call` or `workflow_dispatch`. Its *targets* must expose `workflow_dispatch`: GitHub's dispatch API cannot directly invoke a workflow that only supports `workflow_call`. For reusable-only workflows, use a `jobs.<id>.uses` call instead. The `sha-input` setting is optional; disable it when targets do not declare that input.
